## Docker 冒烟

环境：macOS + OrbStack，Docker 29.8.2，原生 `linux/arm64`。

第一次不带代理的构建在 `go mod download` 失败：

```text
Get "https://proxy.golang.org/github.com/dustin/go-humanize/@v/v1.0.1.mod": EOF
```

代理重试成功：

```sh
docker build -t ansgo:v160-test \
  --build-arg PANEL_VERSION=1.6.0 \
  --build-arg HTTP_PROXY=http://host.docker.internal:1666 \
  --build-arg HTTPS_PROXY=http://host.docker.internal:1666 \
  -f deploy/Dockerfile.allinone .
```

测试资源为容器 `ansgo-v160-round2`，以及同前缀的五个命名卷 `etc/ssl/caddy/sb/acme`。自签证书放在 `/tmp/ansgo-v160-round2/manual-certs`，证书 CN 为 `your-domain.com`。运行命令如下，示例密码仅用于本次隔离测试：

```sh
docker run -d --name ansgo-v160-round2 --label ansgo.test=v160-round2 \
  --privileged --cgroupns=host --tmpfs /run:exec --tmpfs /run/lock \
  --memory 512m --memory-swap 768m --pids-limit 512 --cpus 1 \
  -p 127.0.0.1::15608 \
  -e DOMAIN=your-domain.com -e CERT_MODE=manual \
  -e PANEL_PASS=example-smoke-password -e URL_PATH=/smoke/ \
  -e PANEL_PORT=15608 -e SS_PORT=23458 -e ANYTLS_PORT=23459 \
  -e SOCKS_PORT=23460 -e NAIVE_PORT=23461 \
  -e HTTP_PROXY= -e HTTPS_PROXY= -e ALL_PROXY= \
  -e http_proxy= -e https_proxy= -e all_proxy= \
  -v ansgo-v160-round2-etc:/etc/ansgo \
  -v ansgo-v160-round2-ssl:/etc/ssl/ansgo \
  -v ansgo-v160-round2-caddy:/etc/caddy \
  -v ansgo-v160-round2-sb:/etc/sing-box \
  -v ansgo-v160-round2-acme:/root/.acme.sh \
  -v /tmp/ansgo-v160-round2/manual-certs:/host/manual-certs:ro \
  ansgo:v160-test
```

验证命令包含 `docker exec ... systemctl is-active`、`systemctl show`、`ansgo_memory_mb`、`docker port` 以及 Python 标准库 HTTPS + CookieJar 发起 API 请求。测试驱动及完整输出保留在 `/tmp/ansgo-v160-round2/`，主要命令为：

```sh
python3 /tmp/ansgo-v160-round2/smoke-api.py
python3 /tmp/ansgo-v160-round2/rate-limit.py
python3 /tmp/ansgo-v160-round2/cert-reload.py
```

结果：

- PID 1 为 systemd；manual 同步成功，首次面板和 Caddy active。
- 容器 cgroup `memory.max=536870912`，探测有效预算 512MB。三个 `10-ansgo-limits.conf` 分别生成 sing-box 179M、Caddy 128M、panel 76M；`systemctl show` 的 MemoryMax 与文件一致。
- 三个 unit 均为 `StartLimitIntervalUSec=1min / StartLimitBurst=10`。
- journald：volatile、RuntimeMaxUse=16M、SystemMaxUse=50M；`/var/log/ansgo` 存在且为 0700，panel.json/secrets.env 为 0600。
- HTTPS `api/auth` 返回 `version=1.6.0`，管理员登录成功。
- 连续安装 ss/anytls/socks/naive 均返回 `installed=true, proc_on=true`；新建落地成功；SS→SOCKS→SS→SOCKS→SS 双对象保持一致。
- AnyTLS 健康检测为 active、监听 yes、TCP yes；显式关闭远端后落地检测返回 skip。
- `api/system/info` 返回 docker，两种容器内升级能力均 false；upgrade/auto-upgrade 均 HTTP 400 并有明确 Docker 提示。
- 重启后逐项比较 panel.json/secrets.env 完全一致，sing-box/Caddy/panel 均 active。Docker 随机映射端口在重启后变化，测试驱动通过 `docker port` 重新读取。
- 停机后向配置卷写入 v1.5.37 风格扁平落地和无 schema 数据，ANYTLS_PASS 含空格、美元符号、单引号、反斜杠。再次启动后 schema=2、remote_ss 迁移正确、历史自动启用只在旧 schema 执行，密码在文件/API/生成配置三处一致，sing-box active。
- 临时把容器内 sing-box StartLimitBurst 改为 1，实际触发 `Result=start-limit-hit`；面板 `POST api/repair` 返回 active，CLI `ansgo-admin restart ss` 同样从 start-limit-hit 恢复。测试后删除临时 drop-in，恢复 60/10。
- `POST api/cert/reload` 完整返回后，独立任务重启面板；CLI `ansgo-cert-reload` 也成功延迟重启面板，两次 InvocationID 均变化，三个服务恢复 active。

容器、上述五个卷及测试镜像均按明确名称删除，未执行全局 prune。只保留宿主 `/tmp` 下的测试日志和测试驱动。

```sh
docker rm -f ansgo-v160-round2
docker volume rm ansgo-v160-round2-etc ansgo-v160-round2-ssl \
  ansgo-v160-round2-caddy ansgo-v160-round2-sb ansgo-v160-round2-acme
docker image rm ansgo:v160-test
```

验证范围为 manual 自签证书、配置生成、监听/TCP、API 与迁移；不包含公网 ACME 签发和真实远端 SS/SOCKS 出口连通性。
