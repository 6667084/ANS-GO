# ANS-GO v1.6.0 开发契约（前后端 / 脚本共享）

> 本文件是 v1.6.0 三个并行工作包（WP1 后端、WP2 脚本与部署、WP3 前端 UI）之间的接口约定。
> 旧 API（见 AGENTS.md 与审计）除本文明确修改的部分外**保持兼容**。所有路径均为 `<url_path>api/...`。

## 1. 落地服务数据模型（修复「切换远端类型丢配置」）

### 1.1 新 schema（panel.json `landings[]` 每项）

```json
{
  "id": "1",
  "name": "LA",
  "enabled": true,
  "port": 23456,
  "remote_enabled": true,
  "remote_type": "ss",
  "remote_ss":    { "host": "1.2.3.4", "port": 8388, "method": "2022-blake3-aes-128-gcm", "password": "..." },
  "remote_socks": { "host": "5.6.7.8", "port": 1080, "user": "u", "password": "..." }
}
```

- `remote_type` 只决定**当前生效**的远端协议；切换类型**永不清空**另一类型对象。
- `remote_ss` / `remote_socks` 各自独立保存 host/port/凭证；两者都可以是空对象。
- `remote_enabled` **尊重用户显式值**：不再因「字段齐全」自动置 true。仅在一次性旧数据迁移时（见 1.3）保留 v1.5.35 的自动启用语义。
- 校验：仅当 `remote_enabled=true` 时严格校验**当前生效类型**（SS2022 密钥标准 base64 + 长度；SOCKS 用户/密码非空、不含 `:` 和空白；host 非空；port 1-65535）。非生效类型作为草稿保存，只做长度上限校验（每字段 ≤256 字符）。
- 名称 ≤64 字符；落地数量上限 32。
- ID：panel.json 新增顶层 `landing_next_id`（数字），分配后递增，删除不回收。缺失时取 max(id)+1 初始化。

### 1.2 API

`GET api/landings` → `{landings:[Landing]}`，每项包含：
`id,name,enabled,port,has_keys,password,uuid,remote_enabled,remote_type,remote_ss:{host,port,method,password},remote_socks:{host,port,user,password},remote_via`
以及**兼容镜像字段**（取自当前生效类型）：`remote_host,remote_port,remote_method,remote_user,remote_password`。

`POST api/landings`（创建）与 `POST api/landings/update`（更新）接受：
- `id`（update 必填）、`name`、`port`、`enabled`、`password`（入站 AnyTLS 密码，仅 update）、`remote_enabled`、`remote_type`
- `remote_ss`：对象，**部分合并**（只覆盖出现的键）
- `remote_socks`：对象，部分合并
- 兼容旧扁平字段 `remote_host/remote_port/remote_method/remote_user/remote_password`：写入**请求中 remote_type（缺省为当前类型）对应的对象**。
- 所有校验在拷贝上完成，全部通过后才在锁内提交；任何失败（400/500）内存、panel.json、secrets.env、生成配置均保持原样。

### 1.3 迁移

- 读取时若某落地仍是旧扁平字段（`remote_host` 等），转入 `remote_type` 对应对象（type 空视为 ss），旧字段不再写回。
- panel.json 顶层 `landings_schema` 缺失或 <2 时视为旧数据：执行一次 v1.5.35 自动启用语义（旧字段齐全且有效 → remote_enabled=true），然后写 `landings_schema: 2`。之后不再自动改写 remote_enabled。
- Go（启动迁移）与 ansgo-genconf（python）都必须能**读取**新旧两种格式；**ansgo-genconf 不再回写 panel.json**（纯生成器），迁移落盘只由 Go 面板和 upgrade.sh/entrypoint 执行。

## 2. 系统维护与升级 API（新增）

| 端点 | 方法 | 请求 | 响应 |
|---|---|---|---|
| `api/system/info` | GET | — | `{version, deploy_mode:"metal"\|"docker", arch, auto_upgrade:bool, auto_upgrade_supported:bool, upgrade_supported:bool, mem_total_kb, disk:{total,used,avail} (bytes, 根分区), usage:{backups_bytes, backups_count, journal_bytes, logs_bytes, probe_tmp_bytes}, limits:{panel_mem_max, singbox_mem_max, caddy_mem_max} (字符串，如 "96M"；未知为 "")}` |
| `api/system/check-update` | POST | — | `{ok, current, latest, has_update, url}`；失败 `{error}`。仅用户点击触发，直连 GitHub API（不走环境代理），超时 10s |
| `api/system/upgrade` | POST | `{version?: "vX.Y.Z"}` | 裸金属：`{ok:true, started:true}`（经 `systemd-run --unit=ansgo-upgrade-<ts> /usr/local/bin/ansgo-upgrade --yes [--ver v]` 脱离面板 cgroup 执行，面板会被重启）；Docker：`{ok:false, error, hint}`（提示在宿主执行升级命令）；已有升级在跑：409 |
| `api/system/upgrade-status` | GET | — | `{running:bool, result:""\|"success"\|"failed", log:string}`（log 来自 `/var/log/ansgo/upgrade.log` 末尾 ≤64KB） |
| `api/system/auto-upgrade` | POST | `{enabled:bool}` | `{ok:true, enabled}`；写 panel.json `auto_upgrade:"true"/"false"` 并 `systemctl enable --now / disable --now ansgo-autoupgrade.timer`；Docker 返回 `{ok:false,error}` |
| `api/system/cleanup` | POST | — | `{ok, freed_bytes, log}`；执行 `ansgo-admin prune --yes`（按保留策略清理备份、过期临时文件、vacuum journald 到上限、清会话表过期项） |

- 面板设置 `api/settings` GET 额外返回 `backup_keep`(默认 5)；POST 接受 `backup_keep`（1-30）。

## 3. 文件、日志与资源约定（WP2 实现，WP1 读取）

- 项目日志目录 `/var/log/ansgo/`：`upgrade.log`、`cert-issue.log`、`genconf.log` 等，每个文件写入前若 >1MB 则截断保留末尾 256KB（脚本内实现，不依赖 logrotate）。
- 备份统一在 `/etc/ansgo-backup/` 下（`<类别>-<YYYYmmdd-HHMMSS>[-n]/` 或 `.tar.gz`），旧位置 `/etc/ansgo-backup-*` 由升级迁移/清理脚本识别。每个类别保留最近 `backup_keep` 份（默认 5），且总量 >200MB 时从最旧开始删除。
- 自动升级：`/etc/systemd/system/ansgo-autoupgrade.service` + `.timer`（每周一次 + `RandomizedDelaySec=6h`，`Persistent=true`），执行 `/usr/local/bin/ansgo-upgrade --yes --auto`（仅当有新稳定版本时才动作），**默认关闭**。`--auto` 模式下 nice/ionice 低优先级运行，失败自动回滚。
- `/usr/local/bin/ansgo-upgrade`：已安装的 upgrade.sh 副本（install/upgrade 时刷新）。
- systemd 资源约束：三服务（ansgo-panel / sing-box / caddy）通过 drop-in `/etc/systemd/system/<unit>.d/10-ansgo-limits.conf` 设置 `MemoryHigh/MemoryMax/TasksMax/CPUWeight/OOMScoreAdjust` 与 `Environment=GOMEMLIMIT=...`，数值按宿主内存计算（安装/升级时生成，用户改过的 drop-in 不覆盖）。
- journald：使用项目专属 drop-in `/etc/systemd/journald.conf.d/60-ansgo.conf`（不覆盖用户的 `size.conf`），仅在用户未设置更严格限制时生效。
